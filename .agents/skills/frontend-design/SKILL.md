# Frontend Design

Create a distinctive interface that fits the specific product, audience, and task. First inspect the brief, existing UI, design tokens, and project identity. Do not choose a visual style before understanding what the product helps people do.

## Direction before implementation

Write a short plan covering audience, primary task, context, a visual direction tied to the product, palette, typography, hierarchy, layout, component principles, motion, responsiveness, and accessibility.

Review the direction against the actual brief. Replace choices that feel like defaults you would apply to any product. Do not use generic SaaS cards, gradients, decorative blobs, overly rounded surfaces, or familiar accent palettes unless the product makes them appropriate. Do not let stylistic novelty obscure the main task.

## Build with intention

Use typography, spacing, color, and layout to create hierarchy. Labels should use the user's language and name actions clearly. Keep decoration subordinate to meaning. Motion should respond to a user action or clarify a transition; reduce or remove nonessential motion under prefers-reduced-motion.

Implement within the project's established stack and conventions. Avoid unrequested framework or dependency changes. Check mobile and desktop layouts, keyboard focus, contrast, realistic content lengths, and key interface states. If visual review tools are available, inspect screenshots and adjust the result.

## Self-critique

Before finishing, identify the most important usability issue and visual issue in the result, then resolve what you can. Report the checks performed and remaining limitations.
